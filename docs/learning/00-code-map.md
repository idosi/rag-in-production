# ‏מפת הקוד: איך כל הפרויקט עובד, בלי להיבהל

‏המדריך הזה אחראי על תמונת העל. אם הקוד נראה מסובך, זה בדרך כלל כי רואים 2,500 שורות בבת אחת. בפועל יש כאן **שני סיפורים קצרים** ועוד שלושה סיפורי עזר.

## ‏1. התמונה בשתי שורות

‏אנלוגיה: ספרייה עם ספרן. בלילה, לפני שהספרייה נפתחת, מישהו קורא כל ספר, גוזר אותו לפסקאות ומסדר אינדקס (זה **ingest**). ביום, מישהו שואל שאלה, הספרן שולף 5 פסקאות רלוונטיות וכותב תשובה רק מהן, עם הפניות (זה **ask**).

<div dir="ltr">

```
OFFLINE (פעם אחת):   דפי תיעוד  ->  chunks  ->  וקטורים  ->  Postgres
ONLINE (כל שאלה):    שאלה  ->  וקטור  ->  5 chunks קרובים  ->  Claude  ->  תשובה עם [1][2]
```

</div>

## ‏2. מה יושב איפה

<div dir="ltr">

```
src/rag/

  models.py          האובייקטים שעוברים בין השלבים: Document, Chunk, Answer
  db.py, store.py    הכול על Postgres: יצירת טבלאות, שמירה, חיפוש
  embeddings.py      טקסט -> וקטור (fastembed)
  ingest/            הסיפור הראשון: בניית האינדקס
  retrieval.py       הסיפור השני, חלק א: למצוא chunks
  generator.py       הסיפור השני, חלק ב: Claude כותב תשובה
  pipeline.py        מחבר את retrieval ו-generator לשאלה אחת
  api.py, ask.py     שתי דרכים לשאול: HTTP ו-שורת פקודה

```

</div>

‏הכלל שעוזר: **כל קובץ אחראי על דבר אחד.** `store.py` לא יודע מה זה Claude, ו-`generator.py` לא יודע מה זה SQL.

## ‏3. הסיפור הראשון: ingest (`make ingest`)

‏נקודת הכניסה היא `ingest/__main__.py`, והתגובות בו ממוספרות 1 עד 6. זה הקובץ הכי קל לקרוא ראשון.

1. **‏הגדרות** (`config.py`): קוראים את `.env` ואת ברירות המחדל.
2. **‏הורדה** (`ingest/loader.py`): 48 דפי FastAPI, מוצמדים לגרסה 0.162.0, עם הדוגמאות מוטמעות בטקסט.
3. **‏מסד נתונים** (`db.py`): מתחברים ויוצרים טבלה ואינדקס HNSW אם אינם קיימים.
4. **‏מודל embedding** (`embeddings.py`): נטען לזיכרון.
5. **‏לכל דף** (`ingest/pipeline.py`), ארבעה צעדים:
   - ‏האם הדף השתנה מאז הפעם הקודמת? אם לא, מדלגים (hash).
   - ‏חיתוך ל-chunks לפי כותרות (`ingest/chunker.py`).
   - ‏כל chunk הופך לווקטור של 384 מספרים.
   - ‏מחליפים את שורות הדף בטרנזקציה אחת (`store.replace_document`).
6. **‏ניקוי:** דפים שנעלמו מהמקור נמחקים.

‏מה שכדאי לשים לב: הריצה השנייה מדלגת על הכול ("48 unchanged"). זה נקרא idempotency, ואתה כבר ראית אותו בדוקר.

## ‏4. הסיפור השני: שאלה (`make ask`, או POST ל-`/ask`)

‏הכניסה: `pipeline.py`, הפונקציה `ask`, ארבעה צעדים בלבד:

<div dir="ltr">

```python
sources = self.retriever.retrieve(question, self.top_k)   # 1+2: למצוא
if not sources:                                           # 3: ריק? לא משלמים על Claude
    return Answer(text=NOT_FOUND, sources=[])
return self.generator.generate(question, sources)         # 4: לכתוב תשובה
```

</div>

‏כל מורכבות הפרויקט יושבת בשני הקווים האלה, ואפשר לקרוא אותם בנפרד:

**‏למצוא (`retrieval.py`).** ברירת המחדל היא `rerank`:
1. ‏השאלה הופכת לווקטור.
2. ‏Postgres מחזיר את 10 ה-chunks הכי קרובים (מרחק קוסינוס, אופרטור `<=>`).
3. ‏מודל cross-encoder קורא כל זוג "שאלה + chunk" ונותן ציון מדויק יותר.
4. ‏נשארים 5 הטובים ביותר.

‏המצבים האחרים (`vector`, `hybrid`, ועוד) הם ניסויים ששלב 2 מדד. הם קיימים כדי שנוכל להשוות במספרים, לא כדי שתצטרך להבין את כולם.

**‏לכתוב (`generator.py`).** Claude מקבל את השאלה ואת 5 ה-chunks, ומתבקש לענות **רק** מהם עם `[n]`, או להחזיר משפט קבוע (NOT_FOUND) אם אין תשובה. השאר הוא טיפול בשגיאות, חישוב עלות ומודלים חלופיים (Ollama).

## ‏5. שלושת סיפורי העזר

- **‏API** (`api.py`): עוטף את `pipeline.ask` ב-HTTP. בעלייה בונה את ה-pipeline פעם אחת (טעינת מודלים לוקחת שניות), ובכל בקשה רק קורא לו. `/health` בודק שהמסד זמין.
- **‏Evals** (`evals/`): שאלות עם תשובות ידועות (`evals/golden_set.json`) ומדידה: האם ה-chunk הנכון הגיע ל-5 הראשונים, והאם התשובה נאמנה למקורות. כך החלטנו על המודל (Sonnet) ועל הדירוג מחדש, לפי מספרים.
- **‏Docker ו-CI** (שלב 3א): אורזים את אותו קוד בקונטיינר, ובודקים אוטומטית על כל PR.

## ‏6. סדר קריאה מומלץ (שעה אחת)

1. ‏`models.py`: רק הדיאגרמה בראש ושלושת ה-dataclasses. זה אוצר המילים.
2. ‏`ingest/__main__.py`: ההערות הממוספרות.
3. ‏`pipeline.py`: ארבעה צעדים.
4. ‏`store.py`: `search` ו-`replace_document` בלבד. כאן ה-SQL.
5. ‏`retrieval.py`: רק `Retriever.retrieve` במצב `rerank`.
6. ‏`generator.py`: הפרומפט והחלק שמפרק את הציטוטים.

‏את `evals/`, `rewrite.py` ואת מצבי ה-hybrid אפשר לדלג עד שיהיה צורך.

## ‏7. איך לראות את הזרימה בעיניים

- ‏הרץ `make ask Q="How do I make a query parameter optional?"` ואחר כך הוסף `print` בתחילת `pipeline.ask` כדי להציג `sources`.
- ‏שים breakpoint (ב-VS Code או `breakpoint()`) בשורה הראשונה של `pipeline.ask`, והתקדם עם step into. תראה בדיוק איך שאלה הופכת לתשובה.
- ‏הרץ `make ingest` פעמיים וראה את ההבדל בין ריצה ראשונה לשנייה.

## ‏8. התשובה לראיון ב-60 שניות

‏"בניתי מערכת RAG על תיעוד FastAPI. בצד ה-offline אני חותך את הדפים לפי כותרות, יוצר embeddings ושומר ב-Postgres עם pgvector. בצד ה-online אני מחפש את 10 הקרובים, מדרג מחדש עם cross-encoder ושולח את 5 הטובים ל-Claude, שמחויב לענות רק מהם ולצטט. מדדתי הכול על סט שאלות זהב: ה-reranker שיפר את ה-hit@5, ובחרתי ב-Sonnet לפי רף איכות שקבעתי מראש. את המערכת אריזתי ב-Docker, עם CI שמריץ בדיקות מול Postgres אמיתי."
